# 04 - Layers, components, history (Figma document structure and workflow)

Scope: what Figma does, how it maps to a DOM/CSS source-of-truth editor, priority, pitfalls.
Every Figma claim below is tagged [n] to the Sources list (all fetched this session). Items marked (search-only) came from a WebSearch summary, not a fetched page. Mapping and design advice are my own inference, not Figma claims.

## Core framing
Figma's file is "a tree of objects, similar to the HTML DOM", a map of object IDs to property values [5]. So the layer-tree idea is a natural fit for HTML. The key difference: Figma has a stable ID per object; HTML source has none unless we add one. This drives most pitfalls below.

---

## 1. Layers panel as DOM tree  - MUST (v1)
- Figma: nested parent/child tree; children collapse/expand; "Collapse layers" collapses all except the current selection; new layers go on top of their container or above the selection; icons per type (frame, group, component, instance, text...) [6]. Keyboard: Enter selects child, Tab/Shift+Tab siblings, Shift+Enter parent [1].
- Mapping: layer tree = DOM tree of body. Display name priority: `data-layer-name` > `id` > first meaningful class > tag name (+ short text for text nodes, e.g. `h1 "Welcome..."`). Icon by tag/role (img, svg, button, a, text, container with display:flex/grid -> "auto layout" icon). Selection in tree <-> selection on canvas (iframe overlay).
- Collapse state, hover highlight: editor-only UI state.
- Pitfalls: real pages have deep wrapper-divs and anonymous nodes (text nodes, whitespace, `<script>`, `<style>`, comments) -> filter these out; offer "show all" toggle. Pseudo-elements (::before/::after) are visible in the canvas but not in the DOM tree; show them as read-only pseudo rows or skip in v1. Elements generated by JS have no source location; mark read-only.

## 2. Rename  - MUST (single), LATER (bulk)
- Figma: rename individually or in bulk; bulk modal (Cmd/Ctrl+R) with Match, Rename to, numbering, preview before apply [14].
- Mapping: layer name is not a native HTML concept. Options: (a) `data-layer-name="Hero CTA"` attribute written into source (visible diff noise, survives round-trip, survives Claude Design regenerations only if it preserves attributes - verify); (b) sidecar file `.editor/layers.json` keyed by a stable node key. Recommendation: (a) for names the user types; derived names are never written.
- Pitfall: renaming must NOT change `id`/`class` (would break CSS/JS). Keep naming and identity separate. Figma allows layer-name overrides on instances [9]; analog is per-instance data-layer-name.

## 3. Reorder by drag / reparent  - MUST
- Figma: dragging in the panel changes stacking order (search-only: Figma help search summary). Figma decides reparenting by size/containment when moving on canvas, Space overrides to keep parent [15]. Under the hood each child stores a parent link + fractional-index position as one atomic property; cycles are rejected [5].
- Mapping: reorder = move DOM node (insertBefore) and write the same move in source. Z-order on canvas for positioned elements is separate (z-index) from DOM order; the panel should order by DOM order and show z-index as a property, unlike Figma where list order IS paint order. Drag onto a node = make last child; between rows = sibling. Reject dropping an element into itself/descendant (same cycle rule) and into void elements (img, input, br).
- Pitfalls: moving an element across parents can change inherited styles and selector matches (`.card > p`, `:nth-child`, flex/grid context); show a warning when the moved node's matched rules change (compare computed style before/after). Whitespace/indentation and comments around the moved node in source must travel with it (use a source-preserving AST, not innerHTML re-serialization).

## 4. Hide / lock  - hide SHOULD, lock SHOULD
- Figma: eye toggle and Cmd+Shift+H (search-only); hidden layers greyed. Lock (Cmd+Shift+L): can't move or interact on canvas but still selectable in the panel and editable in properties; locking a parent locks children; child can't be unlocked while parent is locked [13]. The article doesn't say whether lock is persisted in the file [13].
- Mapping: lock = editor-only metadata, never in HTML/CSS (matches brief). Store in `.editor/state.json` keyed by node key. Hide has two meanings: (1) editor-only "hide while editing" via an injected stylesheet `[data-ed-hidden]{display:none !important}` applied in the preview iframe only, never written to source; (2) real `display:none`/`hidden` attr, a style change that must be written. Make these distinct in UI (eye = editor-only; a separate "Hidden on page" property toggle).
- Pitfalls: if editor-only hide leaks into source the page ships hidden. Guard: strip editor attributes/classes on write; test that a no-op session produces a zero-byte diff.

## 5. Layer search / filter  - SHOULD
- Figma: the file-tab article describes no layer-name search; "Find" searches the whole file for text, images, frames, components and replaces text in bulk [6]. (A fuller layer search exists in Figma UI but I did not find it documented in fetched pages.)
- Mapping: filter tree by name, tag, class, id, text content; plus "find by CSS selector". Cheap in a DOM. Also "Identify matching objects" exists in Figma [17 lists title only, not fetched] ~ in HTML = select all elements sharing a class.

## 6. Pages, frames/artboards, sections  - pages SHOULD, frames MUST (as concept), sections LATER
- Figma: unlimited pages per file, each its own canvas [6]. Top-level frames are bold in the layers panel; a top-level frame cannot be nested in group/frame/object [1]. Sections are top-level, can hold any layer type incl. other sections, cannot sit inside frames/groups [16].
- Mapping: page = one `.html` file in the project folder (page list = file list). Frame/artboard = a viewport/breakpoint preview of the same page (e.g. 375/768/1280 iframes side by side) rather than a separate DOM node; that keeps "DOM is the document". Alternative for component-sheet pages: top-level `<section data-frame>` blocks laid out on a canvas. Sections (organizational) = editor-only grouping of iframes on the canvas, LATER.
- Pitfall: multiple viewport iframes editing the same source need one source of truth; edit applies to the one file, all iframes re-render. Media-query-scoped edits (writing a style inside `@media (max-width:...)`) must be an explicit mode, otherwise a tweak at 375px silently rewrites the base style.

## 7. Group vs frame (wrap in container)  - MUST (wrap), LATER (frame properties)
- Figma: groups and frames are both parents; frames add layout grids, auto layout, clip content, constraints [1][15]. "Frame selection" Opt+Cmd+G wraps layers; Ungroup removes the container [1]. An empty frame is not a parent [15].
- Mapping: Group = wrap selection in `<div>` (no styles), Ctrl+G; Frame = wrap in `<div>` with display:flex (auto layout) and optional `overflow:hidden`; Ungroup = replace element by its children. Frame "Resize to fit" [1] = remove explicit width/height.
- Pitfalls: wrapping requires the selected siblings to be contiguous or it must reorder them; wrapper can break selectors (`.parent > .child`), flex/grid item behavior and margin collapsing. Ungrouping a node that carries classes/ids with CSS rules loses those styles. Warn, or refuse when the container has id/class referenced in CSS/JS.

## 8. Components / instances / overrides  - SHOULD (detect+edit-all), LATER (create)
- Figma: components are reusable elements; main component defines properties; instances stay linked and receive updates; can be shared across files via team library [2]. Overridable: text styling, fills/strokes, effects, layout guides, nested instance swap, export settings, layer names. Not overridable: layer order, layer position (incl. in auto layout), constraints, text bounds; those need detach or main-component edit. Reset one/all overrides; detach removes link; "push overrides to main" works only when main is in the same file [9]. When swapping variants, overrides carry over only if layer names match [9].
- HTML equivalents (ranked by fit to "no conversion"):
  1. CSS class = component style; instances = elements sharing the class. Editing a style "on the class" updates all instances; editing "on this element only" = override (inline style or new modifier class). This mirrors Figma main-vs-instance and needs no new format.
  2. Repeated markup (card x 6): detect structurally identical subtrees (same tag/class tree) and offer "edit all like this". Figma's "identify matching objects" [17, title only] is the same idea.
  3. Web components / `<template>`: true instance with slots; only if the project already uses them. Render closed shadow DOM is hard to edit visually, LATER.
  4. Include-style partials: not available in plain static HTML, ignore.
- Key UI to copy: when the user edits a property, the editor must say where the change lands: "this element" / ".btn (12 elements)" / ".btn--primary". A scope picker next to the property is the single most important component-ish feature. Default: class if the element has exactly one class used by >1 element and the user opted in; otherwise element-only.
- Pitfalls: Figma's structural-override limit is a good rule: structural edits (reorder/move/delete child) on one of N identical subtrees = "detach" (it becomes its own thing) or applies to all; ask. Specificity and cascade order: adding a rule to a class may be overridden by a more specific selector; verify by reading computed style after write and warn if the visible result differs from what the user set.

## 9. Variants  - LATER
- Figma: variant = one component in a component set; properties (e.g. state, size) with values; all variants share the same properties; each is a unique combination; sets contain only components; names like `Button/Primary/Large` auto-convert to properties; top-left is default [8]. Figma frames variants as matching code key:value props [12] (the article doesn't explicitly claim class/prop generation).
- Mapping: modifier classes (`.btn.btn--primary.btn--lg`) or `data-variant="primary"` attributes, or pseudo-states (:hover, :disabled) for state variants. Variant picker = a dropdown that swaps classes on the selected element. Detect variants by grouping elements with a common base class and different modifier classes.
- Pitfall: Figma needs all variants to define same properties; CSS doesn't, so many combos are undefined; show "no style for this combo". State variants (hover/focus) need a forced-state toggle in the editor (apply via the devtools-like :hover force, or a class mirror) so the user can edit them.

## 10. Undo / redo  - MUST
- Figma (multiplayer): server keeps the latest value per property per object; last writer wins; no timestamps needed; local changes applied optimistically [5]. Undo is designed so undo, copy, redo back to present leaves the doc unchanged; each undo/redo rewrites the opposite history at that moment; deleted objects' data lives in the deleting client's undo buffer, not on the server [5]. Figma skipped OT as too complex and used a CRDT-inspired LWW design [5].
- Mapping for single-user: store each user action as a patch on the (node key, property) model: `{target, prop, before, after}`; an undo entry = inverse patch; group one drag/scrub into one entry (coalesce on mouse-up; coalesce repeated number-field typing within ~500ms). The undo stack should hold changes to source text as the ground truth: either (a) command log with inverse patches, or (b) snapshots of file text + diff (simple, robust, memory-ok for small projects). Recommend (a) with periodic (b) snapshot for crash safety. Deleted node = keep its serialized source text in the entry (same as Figma's undo buffer [5]).
- Per-property granularity is the right model: CSS declarations are already property-wise, so the "map of id -> property" model fits CSS and attributes directly. Edit to a rule affects N elements; one entry covers all.
- Pitfalls: (1) undo must also restore source file bytes (whitespace) - test round trip. (2) External edits to the files (user's text editor / Claude Code) invalidate the stack; on external change detected, clear the stack or rebase (see 12). (3) Selection state after undo: restore selection to the changed node.

## 11. Autosave and version history  - autosave MUST, named versions SHOULD
- Figma: checkpoint every 30 min and on connection drop/crash; named versions (Cmd+Opt+S) with title and description; restore is non-destructive (adds a checkpoint of the current state before and after restore); paid plans keep full history, free 30 days; checkpoints can't be removed [4]. Offline edits stored in IndexedDB as property changes keyed by node, not whole-file reserialization (avoids slow saves and overwriting newer edits); a version checkpoint is created before and after reapplying diffs, "similar to a Git commit"; no merge-conflict UI built because visualizing 2D design diffs is unsolved [10].
- Mapping: the folder is already the document. Use git inside the project folder (or a shadow `.editor/history/` of snapshots if the folder isn't a repo). Autosave = write source immediately on each committed edit (debounced ~300ms, atomic temp-file + rename). Named version = git tag/commit with message; restore = checkout a snapshot and create a new commit before restoring so it is non-destructive [4]. Show history as a list with before/after previews rendered from snapshots.
- Pitfall: writing the file on every drag frame would thrash watchers/dev servers; write only on commit. Don't auto-commit into the user's own git history without opt-in; use a separate ref/branch or `.editor/` snapshot store.

## 12. "Push back" vs remote edits  - MUST to design now
- Figma lesson: central server authority resolves per-property LWW; client reconnect "downloads a fresh copy of the document, reapplies the offline edits on top, and resumes" [5]; offline diffs are saved as property changes and reapplied to the latest version, with checkpoints as the safety net, not a merge UI [10].
- Mapping: because edits are per-property patches (selector/element + property -> value), the same trick works for push: (1) record the base snapshot at pull time (hash per file); (2) on push, fetch remote current; (3) if a file's remote hash == base, push directly; else do a 3-way merge at the property/node level: our patch log replays onto the new remote text; a patch conflicts only when it touches a (node, property) the remote also changed -> LWW with a prompt per conflict, defaulting to keep remote and show ours as a list; (4) always make a checkpoint before and after push [10].
- Pitfalls: Claude Design may regenerate whole files (class renames, reflow), so node-key matching by path breaks; match by id/data attributes/structure hash and fall back to "manual resolve". Without stable IDs, a re-ordered remote file looks fully changed. Consider injecting `data-ed-id` only in the editor's in-memory copy and stripping on write, or (if Claude Design tolerates it) persisting minimal ids.

## 13. Copy / paste properties  - MUST (style copy), SHOULD (single property)
- Figma: copy a single fill/stroke/effect (Cmd+C/V on the property) or all properties via Copy/Paste as > Copy properties (Opt+Cmd+C / Ctrl+Alt+C), paste applies "any properties that are supported by that layer"; text paste can target a highlighted range or cursor location [7]. Paste to replace swaps a selected object for clipboard content (Shift+Cmd+R) (search-only).
- Mapping: copy properties = capture the element's authored declarations (not the full computed style) for a chosen subset: appearance (background, border, radius, shadow, opacity), typography, layout; paste = write those declarations to the target's rule/inline style per the scope picker. "Paste to replace" = swap element, keep position (parent + index).
- Pitfalls: copying computed style produces hundreds of declarations; copy authored/relevant ones only. Pasting layout properties (position, margin) onto an element in a different layout context gives surprising results; default groups: appearance + typography, layout excluded unless chosen. Also support "copy class list" as a more CSS-native way of sharing a style. Forum reports of copy properties silently doing nothing (search-only) -> always show a toast of what was applied.

## 14. Duplicate  - MUST
- Mapping: Ctrl+D = clone DOM node and insert after the original in source; strip/regenerate `id` (duplicate ids break the page); keep classes. Alt-drag duplicates and moves. Figma's duplicate behavior itself was not fetched (Copy and paste objects page appeared only in listing [17]).
- Pitfall: duplicates share class => later edit with scope=class changes both; make scope visible.

## 15. Comments  - LATER
- Figma: pinned on canvas via C, anchored to top-level frames, components or groups and move with them; not to nested layers; @mentions notify collaborators [11]. (Resolve not covered on fetched page.)
- Mapping: single-user editor: optional "notes" as pins anchored to an element key + offset, stored in `.editor/comments.json`, never in the HTML. Possibly useful as a hand-off to Claude ("fix this"), i.e. comments as prompts. Anchoring only to top-level blocks (as Figma does) is more robust to DOM changes.
- Pitfall: anchors to deep nodes break when the DOM is regenerated; fall back to top-level section.

---

## Recommended v1 cut
MUST: layer tree (DOM, display names, collapse), select sync, rename (data-layer-name), reorder/reparent drag with cycle + void-element guards, wrap in container / ungroup, duplicate, delete, undo/redo (per-property patch stack with coalescing), autosave with atomic writes, editor-only hide/lock stored outside source, scope picker (element vs class), basic copy/paste style, push-back with base hash + conflict check.
SHOULD: layer search, pages = html files list, viewport frames, named versions via git/snapshots, "edit all identical" component detection, single-property copy.
LATER: variants UI, bulk rename, sections, comments, web components, full 3-way merge UI.

## Cross-cutting design rules (inferred)
1. Stable node key: (file, path of tags/nth-child + id if present), plus a hash of subtree; re-resolved after each write.
2. Source-preserving edits: use an HTML/CSS parser with position info (parse5 locations, postcss) and splice text; never re-serialize whole files. Round-trip test: open, change nothing, save = byte-identical.
3. Editor metadata (lock, hidden, collapse, comments, names for non-attribute mode) lives in `.editor/`, excluded from the push.
4. Always show where a style change lands (element / class / media query).
